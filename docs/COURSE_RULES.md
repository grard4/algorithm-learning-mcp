# 内置课程规则与可编辑偏好

`course_rules.py` 是固定规则的唯一来源。它使用不可变元组保存规则，版本与 SHA-256 随只读 `get_course_rules` 返回；没有文件路径参数、环境变量开关或规则写接口。修改规则需修改源码并接受代码审查，不能通过个人偏好操作改变它。

MCP 初始化 `instructions` 直接包含完整规则，而不是仅给一个可忽略的查询链接。CLI／丢失初始化上下文的调用方可以按需调用 `get_course_rules`，已有规则正文无需重复获取。`get_learning_preferences` 保持原返回结构，只读取可编辑偏好；文件缺失、空白、无效、超限和冲突文字都不改变内置规则。

## 本次迁移范围

从已审核的九节精简规则中按段落提取，保留原文语义和“默认、建议、尽量、按需”等条件：

| 原条目 | 固定层 | 留在个人偏好 |
| --- | --- | --- |
| 第 3 节 | 第二段：命名、标识符解释和实现风格 | 第一段 |
| 第 4 节 | 全部：自然写作与加粗 | 无 |
| 第 7 节 | 第二至第八条 | 第一条：UTF-8 与基础 Markdown |
| 第 8 节 | 全部：数字与变量公式化 | 无 |
| 第 9 节 | 第二至第四段 | 第一段：检查职责与 GUI 授权说明 |

旧 GUI 流程与后来的仅静态规则有冲突时，使用仅静态规则；GUI 检查只在用户明确要求及其范围内执行。该边界同时写入初始化指令，避免保留在偏好中的职责说明被删除后引发歧义。内置规则保留任务适用范围，不把课程数学排版无差别用于普通文字。

## 升级与验证

先单独备份原偏好，再部署含内置规则的版本并重新连接 MCP；确认初始化含完整规则且只读查询成功后，才从偏好文件删除上表迁移项。不要在仍运行旧服务时先删除偏好条目。保留的个人规则可继续编辑；不要把私人文件提交到仓库。

“固定”指规则的来源与服务接口不能被偏好配置修改，并非加密防篡改，也不是对外部 AI 行为的绝对保证：拥有源码写权限的维护者可以修改代码；客户端若不传递初始化指令，或模型不遵守指令，服务端无法阻止它在服务之外输出不合规讲义。本服务不接收完整课程文件进行保存，因此本 PR 不冒称已实现课程文件的服务端强制校验，也不修改或自动打开用户文档。

回归验证覆盖偏好删除、空白、非法 UTF-8、超限、目录和试图覆盖规则的文字；真实 stdio 握手验证初始化正文与只读工具返回一致。返回对象可以被调用方本地编辑，但不会改变下一次读取的固定规则。
