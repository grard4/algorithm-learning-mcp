# 聊天注册与同步机制说明

可在本机 `config/discovery_exclusions.json` 保存明确核实为非课程的聊天 UUID 字符串数组。它仅影响自动发现：已登记课程始终优先，手动同步不受影响；文件不存在则无排除，格式无效明确报错。该文件不进入版本控制，不自动按标题推断排除项。移除条目后仍须满足发现快照边界；历史文件可显式登记，不删除历史、归档或游标。资源预算保持不变。

逐文件扫描错误包含不透明 `source_id`，用于本机定位同一源；不暴露绝对路径。失败不会推进游标，修复或追加后仍会重试。

## 各 Agent 共用的 MCP 接入方式

各客户端使用同一套 MCP 服务器实现；需要共享数据的客户端连接同一数据库。开始长期算法课程时，Agent 应从客户端取得真实聊天 ID，再调用 `register_conversation`。已有专题从该学习者自己的数据库解析；新专题须提供明确名称，服务器生成确定性的通用 canonical 值。服务器不能自动发现任意厂商的聊天 ID。单题聊天不应注册为长期专题。

学习记录不会由隐藏的服务器监听器自动捕获。形成值得持久保存的成果后，Agent 须携带来源消息 ID 调用 `update_learning`。这样可明确记录来源与证据，并适用于能够调用 MCP 工具的客户端。无法提供稳定聊天 ID 或无法调用工具的客户端，不能完成这种自动注册与更新。

## 可选的 Codex 会话日志导入

`sync.py` 仅适配 Codex 格式，在指定的 Codex 主目录中扫描 JSONL/Zstandard 会话日志。它不解析 Claude、Cursor 或 VS Code 历史。该功能须主动启用，并且仅指向目标学习者的 Codex 主目录。

- 一次性历史导入：将 `config/initial_threads.example.json` 复制为 `config/initial_threads.json`，用明确选定的 Codex 聊天 ID 和确认的专题名称替换占位内容，再执行 `python sync.py --initial`。每个 ID 必须恰好匹配一个会话日志文件，不能默认导入全部历史聊天。
- 增量发现：在 `config/topic_aliases.json` 中配置希望自动匹配的别名，再执行 `python sync.py --discover --watch --interval 120`。这是轮询，不是实时监听。首次运行时，worker 创建持久化的 `config/discovery_since.txt` 及首次扫描快照；后续按下方 v0.2.2 发现边界处理，缺少可靠创建时间时必须显式登记。默认空别名模板会把不确定专题保留为发现候选，不能猜测 canonical ID 或自动合并有歧义的专题。
- 使用 Ctrl+C 或原启动进程管理器停止监测。服务器不会自动启动该进程。

同一聊天可能由多个 `rollout-*.jsonl` 分片构成。同步器以 rollout 文件名作为分片身份，并为每个聊天分配不重叠的消息序号区间；后续较短的分片不会被误判为整段聊天日志缩短。相同分片重试保持幂等，已导入分片若被缩短或改写则拒绝推进游标并保留已有记录。旧数据库初始化时会从原同步游标及其内容寻址归档回填分片映射；若来源证据不足或映射不一致，迁移会原子失败，不触碰已有学习记录。

`config/topic_aliases.example.json` 是空结构示例，`config/initial_threads.example.json` 说明导入格式。记录包含 `name`、`canonical` 和可选的 `aliases`，具体值由使用者定义。`initial_threads.json` 由 Git 忽略，因为其中的 ID、标题或路径可能暴露私人聊天历史。

## 能力边界

- Codex 专用日志导入不是 MCP 协议能力，也不是通用多 Agent 同步方案。
- 其他客户端可通过 MCP 注册、上下文读取和显式的证据校验更新实现共享；无人值守的历史导入需要另行提供受支持的导出适配器。
- 新聊天自动识别依赖客户端能力。没有客户端事件 API 或已配置的轮询适配器时，注册由当前聊天中的 Agent 调用工具触发。
- 120 秒轮询可能产生一个轮询周期的延迟，且可能无法识别不受支持的日志格式，不能称为实时监听。
- 接受映射前应审核发现候选与冲突。导入器不会把课程计划或助手讲解等同于学习者已经掌握。

第二轮更新：六个旧写接口已停用，系统异常不返回绝对路径；规范化导入及同步采用集中资源预算和有效时间戳校验，超限保留历史和游标。详细兼容变化、恢复及边界见 [输入预算](INPUT_BUDGETS.md)，当前结果见 [第二轮验收](../ROUND2_TEST_MATRIX.md)。

## v0.2.2 发现边界

不使用 ctime 或 mtime 作为创建时间。首次扫描把当前文件路径哈希和设备/inode 身份哈希保存到 `config/discovery-baseline-*.json`；已有路径或身份永不因权限/metadata 修改、更名而自动成为新聊天。已登记聊天优先于排除规则和时间边界，仍可增量同步。排除文件也进入初始快照，取消排除不追溯导入历史。

有可靠 st_birthtime 时，新文件还需出生时间晚于边界且不在未来；没有该字段时，首次清单后新出现的稳定文件身份只进入待确认列表，不读取或导入正文，须显式登记后才能同步。这避免从目录外移入的旧文件被当作新创建聊天。Linux 通常使用此保守路径；Windows Python 3.11 缺少 st_birthtime 时同样处理。缺失/异常身份、时间、损坏快照、根目录身份变化均采取保守策略。首次启用或升级时已有未知聊天不会自动补入，需显式登记。快照不要手工清空来绕过边界；备份 config 并保留人工登记途径。

MCP 对外响应去除 cwd/source_path 等内部字段并提供不透明 source_id；历史 JSON 与正文中的绝对路径也被遮蔽。内部数据库/归档不改写，可信本机诊断可用内部记录定位；路径样式正文可能被保守遮蔽。分页 offset/total_chars 基于对外文本，不能用于原始归档字节定位。此机制不是任意秘密、编码或隐写内容的扫描器。
